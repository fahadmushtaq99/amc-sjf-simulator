A CPU scheduling simulator for the classroom, not the kernel

Every core is a queue.
Every wait costs something.

This simulator runs a client-side model of two dispatch strategies across N virtual CPU cores: classic Shortest Job First, which always trusts the shortest remaining burst, and Adaptive Multi-Core SJF (AMC-SJF), which blends remaining burst with an aging term so long-waiting processes eventually win a core. Nothing here touches your real operating system — it is a pure JavaScript simulation of timestamps, priorities and idle gaps.

Dispatch priority P = 1 / remaining_burst  +  λ × (waiting / total_burst)

06How the two algorithms differ

Normal SJF

Whenever a core goes idle, it picks whichever arrived, unstarted process has the smallest remaining burst time. It is provably optimal for minimizing average waiting time on a single core with all jobs known upfront — but a long job sitting in the queue can be repeatedly skipped by a stream of short arrivals, which is starvation.

AMC-SJF

Each ready process is scored by 1 / remaining_burst + λ × (waiting / total_burst) at the moment a core becomes free. The first term still rewards short jobs; the second term grows the longer a process has waited relative to its own size, so its score eventually overtakes newer, shorter arrivals. This is a form of aging, extended across multiple cores.

Why it needs multiple cores

With more than one core, several processes can be dispatched at the same instant. AMC-SJF treats each core-free event independently: it looks at every core that just became available, re-ranks the ready queue at that exact timestamp, and assigns the best-scoring process — so two cores freeing up together can pick two different processes rather than fighting over one.
